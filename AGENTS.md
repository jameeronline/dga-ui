# DGA-UI Design System

Design-system component library delivered through Storybook. No separate app surface — component work happens in stories.

## Commands

```bash
npm run dev               # Vite dev server
npm run build             # tsc && vite build (typecheck is bundled in; no separate typecheck script)
npm run preview           # vite preview
npm run storybook         # Storybook on port 6006
npm run build-storybook   # static Storybook build
npm run tailwind:build   # npx @tailwindcss/cli -i ./src/styles/input.css -o ./src/styles/output.css --watch
npm run lint              # eslint .
npm run lint:fix          # eslint . --fix
npm run format            # prettier --check .
npm run format:fix        # prettier --write .
npm run generate:icons   # node ./scripts/generate-icons.ts
```

- `npm run build` runs `tsc && vite build` — type errors fail the build; there is no standalone typecheck script.
- After editing `src/styles/input.css`, run `npm run tailwind:build` so the generated `src/styles/output.css` is refreshed (Storybook preview imports it).

## Testing

- `npx vitest run` runs the Storybook suite: Vitest browser mode (headless Chromium via Playwright) using the `storybookTest` plugin.
- ⚠️ `@storybook/addon-vitest` is not installed/declared in `package.json`, so `npx vitest run` currently fails at config load. Install it before investigating further test failures.
- The Vitest config references setup file `.storybook/vitest.setup.ts`, which does not exist in the repo.
- There is no unit test suite; stories (and `src/stories/test/`) are the test surface.

## Architecture Notes

- Components live in `src/stories/components/<category>/<Component>.tsx` with co-located `<Component>.stories.tsx`. Categories: accordion, alerts, avatar, badge, button-group, button-switch, card, dropdowns, features, lists, loader, steps, tabs, tooltip.
- Some components also exist under `src/stories/ui/` and `src/stories/vendor/` (datatables, embla, glidejs, listjs) — check both locations when locating or changing a component.
- Top-level `src/stories/*.stories.ts(x)` (e.g. `Example/Button`) are example/demo stories, not design-system components.
- Components are headless factories returning HTML strings (via `tailwind-variants` `tv`); the Storybook decorator in `.storybook/preview.ts` formats HTML via `js-beautify` before rendering.

## Conventions

- Path aliases: `@/*` → `./src/*`, plus `@/stories/*`, `@/styles/*`, `@/utils/*`, `@/types/*`, `@/config/*`, `@/data/*`. Stale aliases also map `@/components/*` → `./src/components/*`, which does not exist — real component directory is `src/stories/components/`.
- Prettier: printWidth 160, single quotes, trailing commas all. ESLint: strict TS, warns on `any`, unused vars (ignore pattern `^_`).
- tsconfig: strict, `noUnusedLocals`/`noUnusedParameters`, `verbatimModuleSyntax`, `erasableSyntaxOnly`, `noEmit`, bundler moduleResolution; include: `["src", ".storybook/Button.mdx"]`.

## Gotchas

- Vite scaffold leftovers (`src/main.ts`, `src/counter.ts`, `src/style.css`, `src/typescript.svg`) are default Vite+TS template files — design-system work is Storybook-driven, not this entry.
- Icons: `src/icons/icons.generated.ts` is auto-generated by `npm run generate:icons` from `remixicon/icons/<Category>/<name>.svg` — do not edit by hand; add new icons to the list in `scripts/generate-icons.ts`.
- Tailwind CSS v4 (`src/styles/input.css`) with a legacy v3-format `tailwind.config.ts`.
